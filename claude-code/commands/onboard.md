用户会给你一个 GitHub 链接（或者已经在一个项目目录下）。你的任务是：把这个项目完全接手——克隆到正确位置、跑起来、记录一切，让未来任何会话零成本进入状态。

全程自主执行，遇到问题自行排查，不要中途停下来问我。

## 前置：读取规范

1. 读 `~/Opensource/CLAUDE.md`（工作区统一规范，含目录约定、Memory 分工）
2. 读 `~/Opensource/ai-dev-guide.md`（详细开发规范 + 项目模板）

后续所有操作遵守这些规范。

## 第一步：判断位置并克隆

**如果用户给了 GitHub 链接：**

1. 判断项目归属目录：
   - 用户说要 fork / 二开 / 贡献 PR → `~/Opensource/forks/`，用 `gh repo fork --clone` 并配置 upstream
   - 用户说要学习 / 参考 / 试用 / 没特别说明 → `~/Opensource/vendor/`，直接 `git clone`
   - 用户说是自己的新项目 → `~/Opensource/projects/` 对应子目录
2. 如果判断不了，直接问用户一句："这个项目是要 fork 二开还是学习参考？"（仅此一问，之后不再打断）
3. 克隆到对应目录，然后 cd 进去

**如果已经在项目目录下：** 跳过本步，直接从第二步开始。

## 第二步：了解项目

1. 读项目元文件：README.md、CLAUDE.md、AGENTS.md、package.json、Cargo.toml、pyproject.toml、go.mod、docker-compose.yml 等（存在哪个读哪个）
2. 扫描目录结构（顶层 + 关键子目录，不递归太深）
3. 识别：项目名称、用途、技术栈、包管理器、主要目录职责

## 第三步：安装依赖

1. 如果有 .mise.toml 或 .tool-versions，先确认运行时版本匹配
2. 根据包管理器执行安装（npm/pnpm/yarn/bun/uv/pip/cargo/go mod 等）
3. 如果需要额外服务（数据库、Redis 等），用 docker compose 启动
4. 如果需要环境变量，参考 .env.example 创建 .env 并填合理默认值
5. 记录安装过程中的所有异常和解决方法

## 第四步：运行项目

1. 找到开发模式启动命令并执行
2. 确认启动成功（检查端口、日志、进程状态）
3. 启动失败则排查修复，记录踩坑过程
4. 记录：启动命令、端口、耗时、已知的正常警告

## 第五步：写入项目指令文件

在项目根目录创建或更新 `CLAUDE.md`，然后创建软链接 `AGENTS.md → CLAUDE.md`，让所有 Agent 都能读到。

如果项目已有 `CLAUDE.md` 或 `AGENTS.md`，合并补充而非覆盖——保留原有内容，补上缺失的部分。

必须包含的内容：

```
# 项目名称

## 概述
一句话描述。

## 技术栈
- 语言/框架/包管理器等

## 项目结构
关键目录和文件的职责。

## 开发命令
- 安装依赖: `xxx`
- 启动开发: `xxx`
- 运行测试: `xxx`（如果有）
- 构建: `xxx`（如果有）

## 端口
列出所有服务端口。

## 首次运行记录
- **日期**: YYYY-MM-DD
- **状态**: 成功/失败
- **耗时**: 首次编译/安装耗时
- **踩坑点**: 遇到的问题及解决方法
- **已知现象**: 正常但看起来像错误的输出

## 约定
代码风格、提交信息格式、分支策略等（从项目配置中提取）。
```

创建软链接：
```bash
# 如果项目没有 AGENTS.md，或 AGENTS.md 不是软链接
ln -sf CLAUDE.md AGENTS.md
```

如果项目原本有独立的 `AGENTS.md`（非软链接），先将其内容合并到 `CLAUDE.md`，再替换为软链接。

## 第六步：更新 Memory 索引

读 `~/.claude/projects/-Users-yb-Opensource/memory/MEMORY.md`，在项目索引表中添加或更新本项目（项目名、路径、状态、CLAUDE.md 有无）。

Memory 只做索引，不复制 CLAUDE.md 内容。

## 完成后

给一个简短总结：项目是什么、技术栈、怎么启动、有没有踩坑。
