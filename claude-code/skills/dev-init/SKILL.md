为当前项目初始化多会话开发追踪体系（PLAN.md + STATUS.md）。仅在用户明确调用时执行。

全程自主执行，不要中途停下来问我。

## 前置检查

1. 确认当前目录有 `CLAUDE.md`（没有则提示先用 onboard 技能接手项目）
2. 检查是否已有 `PLAN.md` 和 `STATUS.md`
   - **都已存在** → 输出"已初始化过，无需重复执行"，结束
   - **部分存在** → 只创建缺失的文件
3. 读 `CLAUDE.md`，了解项目基本信息

## 创建 PLAN.md

```markdown
# [项目名] 开发计划

## 目标
项目要达成什么 / 要改动什么。

## 方案
架构设计、模块划分、技术选型理由。
如果是 fork / 二次开发，补充：上游仓库地址、基线版本、涉及模块分析。

## 阶段计划

### Phase 1: [名称]
- [ ] 任务 1
- [ ] 任务 2

## 技术决策记录
| 决策 | 选项 | 结论 | 理由 |
|------|------|------|------|
```

## 创建 STATUS.md

```markdown
# [项目名] 开发状态

> 最后更新: [日期]

## 当前阶段
Phase X: [名称]

## 进度
| 功能/改动 | 状态 | 备注 |
|-----------|------|------|

## 已知问题
-

## 下一步
-
```

## 更新 CLAUDE.md

在项目 `CLAUDE.md` 中添加以下内容（如果还没有的话）：

```markdown
## 开始工作前

**必须先读以下文件**：

1. `STATUS.md` — 当前开发进度、已知问题、待办事项
2. `PLAN.md` — 开发计划、架构方案、技术决策

完成工作后，**必须更新 `STATUS.md`**。
```

插入位置：放在"开发命令"之后。如果找不到合适位置，放在文件末尾。

## 填充内容

不要留空模板。根据 CLAUDE.md、README、代码结构、git log 等信息，尽可能填充实际内容。

## 完成后

给一个简短总结：创建了哪些文件、当前状态概要。
