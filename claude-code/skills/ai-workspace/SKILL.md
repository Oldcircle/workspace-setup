# 为 AI 协作组织工作区（四层法）

一句话：**该记的，全放进文件、用索引按需取——不放在脑子里、不放在对话里。**
这样不管哪个 agent、隔了多久、进哪个项目，都能立刻进入状态、自己干活。

## 何时用这个 skill

- 新机器 / 新环境要搭一套「AI 友好」的工作区
- 已有一堆项目乱堆在一起，想整理成 agent 分得清身份的结构
- 想让 agent 跨会话记住进度、不用每次重新交代背景

## 第一层 · 组织层：目录即身份

按「能不能改」把项目分目录，agent 一看路径就知道分寸：

```
~/workspace/
├── projects/   # 原创项目（agent 全权改）
├── forks/      # fork 的开源（谨慎改，别偏离上游）
├── vendor/     # 纯参考 / 学习（只读，绝不改）
├── notes/      # 跨项目笔记
└── configs/    # dotfiles + 工具配置
```

在工作区根 `AGENTS.md` 里维护一张「项目索引」表（项目名 / 路径 / 状态）。agent 启动就读到它，几十个项目瞬间知道在哪、什么状态、哪个正活跃。

## 第二层 · 规则层：AGENTS.md，渐进式加载

- **每个项目一个 `AGENTS.md`**：纯文本说明书——技术栈、目录约定、常用命令、哪些坑别踩。若还想兼容只认 `CLAUDE.md` 的工具，`ln -sf AGENTS.md CLAUDE.md` 软链一份，保持单一 source of truth。
- **渐进式加载**：启动时从当前目录一路向上递归到根，沿途每个 `AGENTS.md` 整份进上下文（个人偏好 + 工作区规则 + 项目说明书，三层自动叠加）；启动目录**之下**的子目录 `AGENTS.md` 不随启动加载——agent 真去读那块的文件时才拉进来。→ 深层专属规则平时零成本。
- **别写 8000 行巨型规则**：每个会话每一轮都在为它付费。规则跟着目录走，token 只为正在碰的代码付。
- **活跃文档清单**：在 `AGENTS.md` 里维护 `## 活跃文档` 小节，列出当前有效的 PLAN / STATUS 等。agent 只读清单里的——不猜、不乱翻到过期文件。

## 第三层 · 记忆层：进度与经验外置成文件

- **PLAN.md**（整体计划，稳定）+ **STATUS.md**（当前进度 + 下次入口，会话交接用）。用配套 `dev-init` skill 一键建。
- **MEMORY.md**：跨项目经验索引（我是谁 / 纠正记录 / 当前活动 / 外部资源），每次会话自动载入；细节拆成子文件，按需读。
- **notes/**：跨项目知识沉淀，靠 `_index.md` 索引；每篇末尾带「关键结论」小节，给 agent 快速提要点。
- 全是同一个模式：**索引 + 按需读**——不硬塞进上下文，用索引指路、需要时才读。

## 第四层 · 治理层：防膨胀（前三层会自然腐化，这层让它可持续）

不治理的话，索引行会越写越长、同一状态记在多处、规则文件膨胀到没人听。三个机制事实决定治理方式：**根规则文件超过 ~200 行后 agent 遵循度显著下降**；Claude Code 的 MEMORY.md **只加载前 200 行/25KB（超出静默截断）**；子目录规则文件**懒加载（细节下沉零开局成本）**。所以：

- **信息归属矩阵**：每条信息只有一个家——定位/技术栈/命令 → 项目 AGENTS.md；进度/下次入口 → STATUS.md；开发史/带日期战报 → git log + STATUS 底部归档区；跨项目经验 → memory 子文件。同一段话禁止写进两处。
- **文档预算**：工作区根文件 ≤200 行/10KB；项目 AGENTS.md ≤200 行（不放带日期状态）；STATUS.md 主体 ≤100 行（历史折进底部归档区）；MEMORY.md ≤150 行/12KB。超预算 = 先下沉再写入，禁止直接追加。
- **时态红线**：说明书只写现在时（半年后仍成立）；STATUS 写现在完成时；过去时只进 git log 与归档区。索引行钩子是"让下个会话决定要不要点进去"，禁日期/版本号/功能清单/成就形容词。
- **更新协议**（自下而上，越往上越薄）：STATUS.md（详）→ 项目 AGENTS.md（仅项目本身变了）→ 工作区索引行（仅状态标签）→ memory（仅跨项目经验）。
- **定期 lint**：每 1–2 周查一次超预算/多处记账/过时条目/失效路径；写入前看周围条目格式——你的条目就是下一个 AI 的模板。

已膨胀工作区的一次性大扫除有现成提示词：`notes/工作区AI文档瘦身治理提示词.md`（盘点 → 备份 → hub 瘦身 → 规则落地 → 项目手术 → 验证，全程零丢失）。

## 一键落地

- 若你克隆了本仓库（workspace-setup）：直接 `bash setup.sh`——建好上述目录、部署工作区规范、装好配套 skill（onboard / dev-init / browser-use）。
- 手动搭：按三层建目录 → 写工作区根 `AGENTS.md`（含项目索引表）→ 每个项目跑 `dev-init` 建 PLAN / STATUS。

## 配套 skill（本仓自带）

- **onboard**：给个 GitHub 链接或在项目目录下，自动克隆到正确位置、跑起来、写 `AGENTS.md`、更新 MEMORY 索引，让任何会话零成本接手。
- **dev-init**：为当前项目建 `PLAN.md` + `STATUS.md`，并在 `AGENTS.md` 加「开始工作前必读」。

## agent 日常必须遵守

1. 进任意项目，先读它的 `AGENTS.md` + 活跃文档清单里的 STATUS / PLAN。
2. 有实质进展就更新 `STATUS.md`（它是会话交接文档，不是日志）。
3. 新项目按目录约定落位；跨项目经验写进 MEMORY / notes，并更新对应索引。
4. 需要背景知识，先查索引（项目索引表 / MEMORY.md / notes/_index.md）再按需读，别全量硬读。
